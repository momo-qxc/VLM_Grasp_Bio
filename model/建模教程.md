## 📚 从 3D 模型到 MuJoCo 的完整流程

### 第一步：准备 3D 模型

#### 支持的格式

MuJoCo 支持以下网格格式：

| 格式 | 推荐程度 | 说明 |
|------|---------|------|
| **OBJ** | ⭐⭐⭐ 推荐 | 通用格式，易于编辑 |
| **STL** | ⭐⭐⭐ 推荐 | 仅几何体，无材质 |
| **MSH** | ⭐⭐ | MuJoCo 原生格式 |
| **GLB/GLTF** | ⭐ | MuJoCo 2.3+ 有限支持 |

#### 格式转换

如果你的模型是其他格式（如 `.glb`, `.3ds`, `.fbx`），可以使用以下工具转换：

1. **Blender**（推荐）：免费开源，导入后导出为 OBJ
2. **在线工具**：[aspose.app/3d/conversion](https://products.aspose.app/3d/conversion)

## 🔄 从 FBX/GLB 转换到 MuJoCo 的完整流程

本节记录了将 Sketchfab 等网站的 3D 模型转换为 MuJoCo 可用格式的完整流程。

### 步骤 1：安装 Blender

```bash
# 推荐使用 snap 安装（避免镜像源问题）
sudo snap install blender --classic

# 或者从官网下载
# https://www.blender.org/download/
```

### 步骤 2：下载模型

从 Sketchfab 等网站下载模型时，**推荐下载 FBX 格式**（原始格式，包含完整纹理）。

> ⚠️ **注意**：GLB 格式虽然方便，但有时不包含嵌入纹理，转换后会丢失材质。

### 步骤 3：解压并转换

```bash
# 1. 解压下载的文件
unzip microscope.zip -d microscope_fbx
cd microscope_fbx/source
unzip Microscope.zip

# 2. 使用 Blender 转换 FBX 到 OBJ
blender --background --python-expr "
import bpy
import glob

bpy.ops.wm.read_factory_settings(use_empty=True)

# 查找 FBX 文件
fbx_files = glob.glob('/path/to/your/model/**/*.fbx', recursive=True)
if fbx_files:
    bpy.ops.import_scene.fbx(filepath=fbx_files[0])
    bpy.ops.wm.obj_export(
        filepath='/path/to/output/model_textured.obj',
        export_materials=True,
        path_mode='COPY'  # 复制纹理文件到输出目录
    )
    print('转换完成！')
"
```

### 步骤 4：分析模型尺寸

使用 `check_size.py` 脚本分析模型的实际尺寸：

```python
# microscope/check_size.py
def get_obj_bounds(filepath):
    min_x = min_y = min_z = float('inf')
    max_x = max_y = max_z = float('-inf')
    
    with open(filepath, 'r') as f:
        for line in f:
            if line.startswith('v '):
                parts = line.split()
                x, y, z = float(parts[1]), float(parts[2]), float(parts[3])
                min_x, max_x = min(min_x, x), max(max_x, x)
                min_y, max_y = min(min_y, y), max(max_y, y)
                min_z, max_z = min(min_z, z), max(max_z, z)
    
    return {
        'width': max_x - min_x,
        'depth': max_y - min_y,
        'height': max_z - min_z
    }
```

运行结果示例：
```

如果目标高度是 30.0cm，推荐缩放比例: 0.7164
```

### 步骤 7：设置默认相机视角

在 `test_lab_equipment.py` 中使用 `launch_passive` 设置初始相机：

```python
with mujoco.viewer.launch_passive(model, data) as viewer:
    # 设置相机对准显微镜（顶层架子）
    viewer.cam.lookat[0] = 0.0   # x
    viewer.cam.lookat[1] = -0.2  # y  
    viewer.cam.lookat[2] = 1.5   # z（顶层架子高度）
    viewer.cam.distance = 2.0
    viewer.cam.azimuth = 135
    viewer.cam.elevation = -15
    
    while viewer.is_running():
        step_start = time.time()
        mujoco.mj_step(model, data)
        viewer.sync()
        
        # 控制帧率以获得顺滑的交互
        time_until_next_step = model.opt.timestep - (time.time() - step_start)
        if time_until_next_step > 0:
            time.sleep(time_until_next_step)
```

### 第二步：检查模型单位

**这是最常见的问题！** 不同软件使用不同的单位：

| 来源 | 常见单位 | 转换到米 |
|------|---------|---------|
| Blender 默认 | 米 | scale = 1 |
| 3ds Max | 厘米 | scale = 0.01 |
| SketchUp | 英寸 | scale = 0.0254 |
| CAD 软件 | 毫米 | scale = 0.001 |

**如何判断？** 打开 OBJ 文件，看顶点坐标的数值范围。例如：
```
# 货架模型的坐标范围是 -50 到 50，说明是厘米
v -47.982971 0.000000 1.465458
```

### 第三步：创建 MuJoCo XML 文件

#### 基本结构

```xml
<?xml version="1.0" encoding="utf-8"?>
<mujoco model="my_model">
    <compiler angle="radian" />
    
    <option gravity="0 0 -9.81" timestep="0.002"/>
    
    <asset>
        <!-- 加载网格，scale 用于单位转换 -->
        <mesh name="my_mesh" file="path/to/model.obj" scale="0.01 0.01 0.01"/>
        <material name="my_material" rgba="0.5 0.5 0.5 1"/>
    </asset>
    
    <worldbody>
        <body name="my_object" pos="0 0 0">
            <geom type="mesh" mesh="my_mesh" material="my_material"/>
        </body>
    </worldbody>
</mujoco>
```

#### 关键参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `scale` | 缩放因子 | `scale="0.01 0.01 0.01"` 将厘米转为米 |
| `pos` | 位置 (x, y, z) | `pos="0 0 1"` 在 z=1m 处 |
| `euler` | 欧拉角旋转 (弧度) | `euler="1.5708 0 0"` 绕 X 轴转 90° |
| `quat` | 四元数旋转 | `quat="0.7071 0.7071 0 0"` 绕 X 轴转 90° |

## 🔧 解决常见问题

### 问题 1：模型方向不对（平躺而非竖立）

**现象**：导入的模型躺在地上，而不是像预期那样竖立。

**原因详解**：

不同的 3D 软件使用不同的坐标系约定：
- **Blender、3ds Max 等**：通常使用 **Y 轴向上** 的坐标系
- **MuJoCo**：使用 **Z 轴向上** 的坐标系（符合物理学惯例，Z 代表高度）

因此，当你导入一个在 Blender 中竖立的模型时，它在 MuJoCo 中会"躺下"，因为原本指向 Y 轴（上方）的方向现在指向了 MuJoCo 的 Y 轴（前方）。

**解决方案**：绕 X 轴旋转 90 度，使原本的 Y 轴对齐到 MuJoCo 的 Z 轴

```xml
<!-- 方法 1：使用欧拉角（弧度制） -->
<body name="shelf" euler="1.5708 0 0">  <!-- 1.5708 ≈ π/2 = 90° -->

<!-- 方法 2：使用四元数（更精确，避免万向锁） -->
<body name="shelf" quat="0.7071 0.7071 0 0">
<!-- 四元数格式：w x y z，这里表示绕 X 轴旋转 90° -->
```

**小贴士**：如果不确定需要怎么旋转，可以在 MuJoCo 中尝试不同的欧拉角组合，直到找到正确的方向。

### 问题 2：物体固定无法移动

**现象**：在仿真中双击物体想要拖动，但物体纹丝不动，好像被焊在了原地。

**原因详解**：

MuJoCo 中的物体默认是**固定在世界坐标系**的。这是因为 MuJoCo 最初是为机器人学设计的，机器人通常需要一个固定的基座。

在 MuJoCo 的物理引擎中：
- **没有关节的 body**：被视为世界的一部分，完全固定
- **有关节的 body**：可以相对于父 body 运动

如果你想让一个物体自由移动（比如可以被拾取的物品），需要给它添加一个**自由关节（free joint）**。自由关节允许物体在 6 个自由度上移动（3 个平移 + 3 个旋转）。

**解决方案**：添加 `type="free"` 的关节

```xml
<body name="movable_object">
    <!-- 添加自由关节使物体可以自由移动 -->
    <joint name="object_free" type="free" damping="0.1"/>
    <geom type="mesh" mesh="my_mesh"/>
</body>
```

**参数说明**：

| 参数 | 说明 | 建议值 |
|------|------|--------|
| `type="free"` | 6 自由度关节 | 必需 |
| `damping` | 阻尼系数，越大物体停止得越快 | 0.1 - 1.0 |

**注意**：如果某些物体（如桌子、架子）确实需要固定，就不要添加关节。

### 问题 3：物体穿透其他物体

**现象**：物体直接穿过地面或其他物体，没有发生碰撞。

**原因详解**：

MuJoCo 使用**碰撞对（collision pairs）**系统来决定哪些几何体之间会发生碰撞。这个系统由两个关键参数控制：

1. **`contype`（碰撞类型）**：一个位掩码，表示这个几何体"是什么类型"
2. **`conaffinity`（碰撞亲和性）**：一个位掩码，表示这个几何体"会与什么类型碰撞"

**碰撞规则**：只有当 `(geom1.contype & geom2.conaffinity) || (geom2.contype & geom1.conaffinity)` 为真时，两个几何体才会碰撞。

简单来说：
- 如果 `contype=0`：这个几何体不会主动参与任何碰撞
- 如果 `conaffinity=0`：这个几何体不会"感知"其他物体

**常见错误**：只设置了视觉几何体，没有设置碰撞几何体。

**解决方案**：分离视觉几何体和碰撞几何体

```xml
<!-- 视觉几何体（仅用于显示，不参与碰撞） -->
<geom name="visual" type="mesh" mesh="my_mesh" 
      contype="0" conaffinity="0"  <!-- 都设为 0 = 不碰撞 -->
      group="2"/>                   <!-- group 用于在 viewer 中分组显示 -->

<!-- 碰撞几何体（参与物理碰撞） -->
<geom name="collision" type="mesh" mesh="my_mesh" 
      contype="1" conaffinity="1"  <!-- 都设为相同的非零值 = 互相碰撞 -->
      condim="6"                    <!-- 碰撞维度 -->
      rgba="0 0 0 0"/>              <!-- 透明，不显示 -->
```

**`condim` 参数详解**：

| 值 | 含义 | 使用场景 |
|---|------|---------|
| 1 | 仅法向力（无摩擦） | 冰面、滑轮 |
| 3 | 法向力 + 2D 切向摩擦 | 一般物体 |
| 4 | 法向力 + 2D 摩擦 + 扭转摩擦 | 需要扭转阻力 |
| **6** | 全维度摩擦（推荐） | 大多数情况 |

### 问题 4：物体在表面滑动不停

**现象**：放在桌面或架子上的物体会慢慢滑动，无法静止。

**原因详解**：

物体滑动的原因可能有多个：

1. **摩擦力不足**：默认摩擦系数可能太低
2. **表面不水平**：碰撞盒有微小的倾斜
3. **数值误差**：物理求解器的精度问题

MuJoCo 中的摩擦力由 `friction` 参数控制，它是一个三元组 `"f1 f2 f3"`：
- **f1**：滑动摩擦系数（最重要）
- **f2**：扭转摩擦系数
- **f3**：滚动摩擦系数

当两个表面接触时，实际摩擦力 = 两个表面摩擦系数的几何平均值。

**解决方案**：

#### 步骤 1：增加摩擦力
```xml
<geom name="collision" type="box" 
      friction="2 0.5 0.001"   <!-- 高滑动摩擦 -->
      condim="6"/>             <!-- 完全摩擦模式 -->
```

#### 步骤 2：确保碰撞盒完全水平
```xml
<!-- 使用 quat="1 0 0 0" 确保无旋转（完全水平） -->
<body name="shelf_collisions" pos="0 0 0" quat="1 0 0 0">
    <geom name="layer" type="box" size="0.5 0.5 0.02"/>
</body>
```

#### 步骤 3：如果还滑动，检查物理参数
```xml
<option solver="Newton" iterations="100"/>
```

### 问题 5：物体抖动不稳定

**现象**：物体倒下后不断抖动，无法静止。

**原因详解**：

抖动的根本原因是**复杂 mesh 碰撞体在边缘接触时的数值不稳定性**。

当一个物体正放时（底面平坦接触）：
- 接触点均匀分布
- 物理求解器容易找到稳定解

当物体倒下时（边缘或曲面接触）：
- 接触点集中在少数边缘位置
- Mesh 的不规则三角面会产生很多微小的接触点
- 求解器在这些接触点之间来回"弹跳"，导致抖动

这是 MuJoCo（以及大多数物理引擎）中使用复杂 mesh 碰撞的固有限制。

**解决方案**：

#### 方案 A：使用凸包碰撞体（推荐）

凸包是包围原始几何体的最小凸多面体。它大大简化了碰撞几何：
- 顶点数减少（例如：5659 → 143）
- 边缘更平滑
- 碰撞计算更稳定

```bash
# 安装依赖
pip install trimesh scipy numpy

# 生成凸包
python generate_convex_hull.py
```

```xml
<!-- 视觉用原始 mesh（保持外观） -->
<geom name="visual" type="mesh" mesh="original_mesh" contype="0"/>

<!-- 碰撞用凸包 mesh（更稳定） -->
<geom name="collision" type="mesh" mesh="convex_mesh" contype="1"/>
```

#### 方案 B：使用更精确的求解器

```xml
<option 
    solver="Newton"        <!-- Newton 求解器比 PGS 更精确 -->
    iterations="100"       <!-- 更多迭代次数 -->
    tolerance="1e-10"      <!-- 更严格的收敛条件 -->
    noslip_iterations="5"  <!-- 防止接触点滑移 -->
/>
```

#### 方案 C：添加接触稳定性参数

```xml
<geom name="collision" type="mesh" mesh="my_mesh"
      solref="0.01 1"              <!-- 接触柔度 -->
      solimp="0.9 0.99 0.001"/>    <!-- 接触阻抗 -->
```

**参数说明**：
- `solref="时间常数 阻尼比"`：控制接触的"弹性"
- `solimp="最小值 最大值 宽度"`：控制接触约束的满足程度

#### 方案 D：接受轻微抖动

如果上述方法都无法完全消除抖动，这是物理仿真的正常现象。在实际应用中：
- 正常使用时物体正放，不会抖动
- 抖动通常很轻微，不影响仿真结果
